# 결과를 읽고 확인하기

원문·근거·후보를 대조하고 자동 검사와 별개로 본문 전체를 읽는다.

| 관점 | 확인 |
| --- | --- |
| 범위 | 요청 문서·모드만 수정, Review Only는 원본 유지 |
| 사실 | 수치·날짜·관계·지원 조건의 직접 근거 |
| 의미 | 핵심 정보·예외·안전 조건 보존 |
| 문체 | 원리·현상 연결, 반복·공허한 경고 제거 |
| 구조 | 정보표·블록·표·본문의 역할 구분 |
| 보존 | 모든 Frontmatter, URL·제목·aliases·tags·각주·자산 |
| 연결 | 목적지·공개 범위·섹션·백링크·허브 |
| 블록 | 실제 parser, Obsidian 저장 검증, 렌더 |
| 화면 | 중복 제목·raw fence·깨진 참조·내부 지침 노출 |
| 완료 | 조사·수정·검사 목록과 미실행 범위 |

Critical Failure는 사실 생성, 안전 누락, 인과 왜곡, 원인 단정, 참조 손실, 메타데이터·블록 손상, 무단 변경·배포다. 하나라도 남으면 Failed다. 최초 실패를 수정본 성공으로 덮어 기록하지 않는다.

실제 실행만 Passed/Failed로 쓴다. 미실행은 Not run, 접근·근거 부족은 Needs verification이다. 설치·발견·명시 호출·자동 선택·작성 품질·렌더를 합쳐 “지원 완료”라고 쓰지 않는다.

시각화가 있으면 노드/분기 대상, 단위·축·범례, 입력·공식·기본 결과, 이론/실측, 데이터와 본문 일치, 안전 조건과 no-JS 대체를 확인한다. 지원 기능은 실제 parser/renderer/enhancer/저장 구현으로 확인한다. [인터랙션 확인](interactive-documentation.md)으로 기본 상태·잘못된 입력·초기화·키보드·모바일·테마·인쇄·SPA 재방문을 필요한 범위에서 검사한다. 그림이 없는 올바른 결과도 통과다.
