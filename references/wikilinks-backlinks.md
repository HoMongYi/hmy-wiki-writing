# 링크·별칭·앵커·각주

새 링크는 실제 파일명, title·aliases, 섹션을 확인한다. 동명 문서가 있으면 Vault 루트 기준의 명확한 경로를 사용한다. 구문은 `[[문서명]]`, `[[문서명|표시명]]`, `[[문서명#섹션]]`이다. 이 설명의 “문서명”은 실제 목적지가 아니다. 표 안의 alias 파이프 escape와 임베드 `![[...]]`를 구분한다.

HMY Vault 감사는 파일명·title·aliases를 검색한다. Quartz crawl-links는 slug·shortest 전략, aliases는 별도 리디렉션도 사용한다. 감사 성공이 브라우저 앵커·백링크의 성공은 아니다.

가능하면 canonical 파일을 링크하고 필요한 이름은 표시명으로 쓴다. alias 목적지를 쓰면 실제 리디렉션·앵커·백링크를 확인한다. 현재 확인한 Quartz 별칭 파일은 Vault 루트에 생성되고 리디렉션 후 fragment가 사라질 수 있다. 섹션 링크는 canonical 파일명과 실제 heading을 사용한다. 섹션은 실제 heading과 생성 HTML id를 확인한다. 공백 치환만으로 앵커를 예측하지 않는다. 중복 heading에는 접미사가 붙을 수 있다.

기존 URL과 앵커를 유지한다. 이동 전에 유입 링크를 조사한다. 깨진 기존 링크는 보존 검사를 통과해도 남은 오류다.

핵심 용어의 첫 의미 있는 등장에 링크하고 반복되는 모든 단어·표 셀에 붙이지 않는다. 백링크 수를 위한 상호 링크를 만들지 않는다. 공개 제외 문서는 공개 독자의 목적지가 될 수 없다.

각주는 짧은 약어·예외·역사적 부연에 쓴다. 정의·참조·ID를 보존하고 핵심 설명·안전 경고는 본문에 둔다. [허브 예시](../examples/wikilinks-hub.md)는 독립 fixture의 실제 목적지를 사용한다.
