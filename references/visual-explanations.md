# 설명 형식 선택

독자가 풀어야 할 질문을 한 문장으로 정한다. 텍스트만으로 관계와 조건이 명확하면 시각 자료를 추가하지 않는다. 시각화 개수나 새 컴포넌트 사용률로 품질을 평가하지 않는다.

| 독자의 질문 | 우선 형식 | 선택 조건 |
| --- | --- | --- |
| 무엇이며 왜 이런 현상이 생기는가 | 일반 문단 | 정의·원인·조건을 연결 |
| 몇 개 항목의 값이나 지원 조건이 어떻게 다른가 | Markdown 표 또는 hmy-spec | 동일한 속성을 실제로 비교 |
| 어떤 부품이 어떻게 연결되는가 | 기존 도식, Mermaid 또는 hmy-diagram | 구성 요소와 연결 자체가 설명의 중심 |
| 숫자의 차이·추세가 중요한가 | 표 또는 hmy-spec.plot | 단위·같은 조건·근거 데이터 확보 |
| 입력을 바꾸면 어떤 관계가 달라지는가 | hmy-explorer | 구현된 계산 종류와 적용 범위에 들어감 |
| 어떤 순서로 진행하는가 | 본문 또는 hmy-guide | 실제 순서가 있는 절차 |
| 관찰 결과에 따라 어디로 가는가 | hmy-diagnosis | 유효한 분기와 안전한 후속 조치가 있음 |
| 사건이 어떻게 이어졌는가 | 문단, hmy-timeline, hmy-company-event | 공식 날짜·관계가 확인됨 |
| 신호의 논리적 순서는 무엇인가 | hmy-signal | 개념 순서만 설명하며 실측 시간·전압 아님 |
| 두 이미지의 어떤 차이가 중요한가 | hmy-media.compare | 각각의 권리·alt·같은 비교 조건 확보 |

이름이 있는 것과 설치된 프로젝트에서 사용할 수 있는 것은 다르다. [프로젝트 연결](obsidian-quartz.md)과 [블록 확인](hmy-blocks.md)으로 현재 parser·renderer·enhancer·플러그인을 확인한다. 지원이 없으면 본문·표·Mermaid·정적 자산으로 설명한다. 필요한 기능의 별도 설계는 요청된 경우에만 보고하며 실행 가능한 Markdown과 섞지 않는다.

## 구조·관계·데이터 경로

기존 자산을 먼저 검색한다. 같은 관계를 정확하게 설명하는 그림이 있으면 재사용한다. hmy-diagram은 요소 선택과 연결 강조가 이해를 돕는 작은 구조에, Mermaid는 정적인 흐름·그룹 표현에 적합하다. 회사 관계는 프로젝트의 기존 entity/relations를 확인하고 별도 소유권 데이터베이스를 만들지 않는다.

그림의 노드·화살표·그룹마다 본문에서 의미를 설명할 수 있어야 한다. 방향은 요청 흐름인지 데이터 이동인지 관계 방향인지 밝힌다. 양방향 버스를 단방향 데이터 경로처럼 단정하지 않는다. 캐시 그림은 공유 범위·생략한 계층과 제품별 예외를, 메인보드 그림은 CPU 직결·칩셋 공유 조건을 설명한다. 특정 플랫폼의 Lane 수·물리 배선·핀 배열을 추정하지 않는다.

자동 배치에서는 노드 배열 순서 때문에 연결선이 다른 노드를 가로지를 수 있다. 실제 렌더에서 본문에 없는 중간 경유지처럼 보이는지 확인하고 순서·배치를 조정한다. 경로를 명확하게 그릴 수 없으면 기존 도식이나 Mermaid로 설명한다.

새 개념도에는 실제 형상·위치·축척·시간을 나타내지 않는 범위를 캡션이나 description에 쓴다. 규격 커넥터·슬롯·핀 식별에는 정확한 모델·리비전의 공식 도해가 필요하다. SVG·Mermaid·HMY Block의 설명과 본문·참고 자료가 모순되지 않는지 확인한다.

Mermaid는 프로젝트가 지원하는 기본 문법과 접근 가능한 제목·설명을 사용한다. 임의 JavaScript, click callback, 외부 코드를 삽입하지 않는다. 단순 장식 이미지나 본문 전체를 대체하는 그림은 만들지 않는다.

## 독자가 볼 수 있는 결과

기본 상태에서 핵심 관계와 적용 한계를 읽을 수 있어야 한다. 색상 외 이름·연결 문장·대체 표를 제공하고 작은 화면·확대·키보드·인쇄에서도 설명이 남는지 확인한다. 최신 로컬 구현의 지원과 운영 사이트에 배포된 지원은 별도로 확인한다.

[예시 안내](../examples/visual-documentation.md), [수치 설명](data-visualization.md), [인터랙션 확인](interactive-documentation.md)을 필요한 경우에만 읽는다.
