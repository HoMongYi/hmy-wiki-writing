# 하드웨어 진단

관찰된 증상에서 출발한다. 장치·연결 방식·화면·재현 조건을 먼저 나눈다. “SSD가 안 보임”을 곧바로 M.2 NVMe 문제로 좁히지 않는다. SATA, PCIe NVMe, USB 브리지, RAID/VMD 경로의 확인 위치는 다르다.

증상→가능 원인→이유→확인 방법→순서→교차 시험→해석→후속 조치를 연결하되 고정 목차로 강제하지 않는다. 실제 관찰·가설·앞으로 할 시험을 분리한다. 펌웨어 목록과 부팅 항목은 다르고 별도 컨트롤러 화면도 있으므로 화면 부재를 장치 고장과 동일시하지 않는다.

각 확인에는 대상·방법·결과별 의미·다음 행동을 붙인다. 호환성이 확인된 장치·슬롯·케이블로 한 변수씩 교차한다. 시험하지 않았다면 통과 결과를 만들지 않는다.

DRAM LED는 초기화 단계의 단서다. DIMM 외에도 CPU 메모리 컨트롤러·소켓·보드·펌웨어가 관여한다. SMART나 벤치마크 한 값도 단독 불량 판정이 아니다.

## 행동 가까이에 안전 조건

기존 데이터가 있는 SSD의 초기화·포맷·새 볼륨 생성은 기본 진단 단계가 아니다. 데이터가 중요하면 쓰기 작업을 멈추고 보존·복구 경로를 우선한다. 부품 재장착은 전원 분리와 모델별 절차를 함께 설명한다. BIOS 갱신·전압 변경·핀 조작을 일반 해결책으로 넣지 않는다.

시험 후 개선돼도 장시간 부하·온도·절전 복귀까지 확대하지 않는다. 분기 블록이 데이터 보호·물리 작업 조건을 대체하지 않게 한다. [SSD 예시](../examples/troubleshooting.md)를 참고한다.

선택형 진단은 [인터랙티브 설명](interactive-documentation.md)에 따라 유효한 고유 ID와 yes/no 또는 choices를 작성한다. detail/action으로 점검과 후속 조치를 구분하며 안전 조건을 선택 뒤에만 숨기지 않는다. 현재 지원되는 enhancer의 클릭 이동과 정적 전체 경로는 별도로 확인한다.
