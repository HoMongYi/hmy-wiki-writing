# 한국어 기술 설명

기본은 객관적인 ~다체다. 기술의 구조·동작·조건을 주어로 삼고, 명령형은 실제 점검·조립 순서에 쓴다. 특정 회사 직원이나 교육생을 전제하지 않는다.

문단 하나는 하나의 생각을 발전시킨다. 정의 다음에는 구조, 원리, 실제 영향, 예외 중 필요한 설명을 잇는다. 동일한 목차·문단 길이를 강제하지 않는다. 한 문장이 길어도 조건과 결론이 정확하게 연결되면 기계적으로 나누지 않는다.

## 고칠 부분과 유지할 부분

- 불필요한 피동·명사화·번역투, 같은 주어와 결론의 반복을 고친다.
- “중요한 역할”, “확인이 필요”, “단정할 수 없다”만 남은 문장은 무엇이 어떻게 달라지는지 설명한다. 필요한 기술적 한계를 지우는 금지어 치환은 하지 않는다.
- 표는 값과 비교, 본문은 이유와 관계를 맡는다. 표의 모든 셀을 본문에서 반복하지 않는다.
- 도입의 목차 예고, 끝의 형식적인 요약을 줄인다.
- 정확하고 자연스러운 문장은 바꾸지 않는 것이 올바른 편집이다(Deliberate Non-Change).
- Light Edit의 사실 수정은 요청 범위와 구분한다. 오류는 근거와 함께 보고하고 문체 교정을 이유로 지원·안전 조건을 삭제하지 않는다.

전: M.2 슬롯에 SSD가 장착 가능하다는 사실만으로 사용 가능 여부를 판단할 수 없으며, 해당 슬롯의 지원 규격에 대한 확인이 필요하다.

후: M.2 슬롯은 제품에 따라 SATA 또는 PCIe 연결을 지원한다. SSD의 크기와 키 홈이 맞더라도 메인보드가 해당 연결 방식을 지원해야 사용할 수 있다.

길이보다 물리적 장착과 연결 방식의 조건이 드러나는지가 중요하다. 여러 문단의 보존은 [Light Edit 예시](../examples/light-edit.md)를 본다.

시각 자료의 한계도 기술의 조건으로 쓴다. 예를 들어 “캐시 용량과 공유 범위는 CPU 모델에 따라 다르다”처럼 설명한다. “자료가 주어지지 않아 수치를 덧붙이지 않는다” 같은 작성 상황·처리 결정은 별도 보고에 둔다.
