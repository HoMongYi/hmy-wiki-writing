# Repository-wide Improvement

사용자가 전체 또는 지정 영역의 실제 수정을 요청했을 때 사용한다. 단순 Review Only 요청이면 [감사](knowledge-audit.md)로 끝낸다.

1. 공개 범위와 요청 범위로 전체 대상 목록을 만든다. 제외 목록과 원본 상태를 기록한다.
2. 유형·품질·중복·연결을 조사하고 위험과 독자 영향으로 우선순위를 정한다.
3. 문서마다 KEEP 또는 여섯 모드 중 맞는 작업을 선택한다. 같은 문서를 여러 에이전트가 중복 분석·수정하지 않는다.
4. 묶음별로 근거를 확인하고 실제 문서를 수정한다. 사실·메타데이터·블록·참조·안전 조건을 보존한다. 블록·그림의 수를 늘리는 목표는 두지 않는다.
5. 묶음의 링크·허브·상반 설명을 재검토하고 전체 목록에 결과를 반영한다.
6. 실제 프로젝트 검사와 Quartz·Obsidian 확인을 실행 가능한 범위에서 수행한다. 원본을 건드릴 수 없는 평가라면 독립 사본을 사용한다.
7. 대상별 수정·유지·보류·실패, 검사 범위, 미조사·미검증 목록을 보고한다.

대표 몇 개를 수정한 뒤 전체 완료로 선언하지 않는다. 일부에서 멈추면 완료한 목록과 남은 목록을 넘긴다. 게시·push는 이번 요청의 권한을 확인한다. 이 workflow는 운영 배포 권한을 추가하지 않는다.
