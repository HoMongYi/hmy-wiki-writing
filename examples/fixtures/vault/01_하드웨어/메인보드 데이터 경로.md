# 메인보드 데이터 경로

메인보드는 CPU·메모리·확장 장치 사이의 연결 경로를 제공한다. 같은 모양의 슬롯이라도 CPU에 직접 연결되는지, 칩셋과 업링크를 공유하는지에 따라 동시에 사용할 수 있는 자원이 달라진다. [[PCI Express]]의 세대와 링크 폭은 이 경로를 읽는 데 필요한 별도의 조건이다.

```hmy-diagram
title: CPU와 장치의 논리적 연결
description: 요청 경로를 단순화한 개념도다. 화살표는 실물 배선·핀 배열·고정 Lane 수나 단방향 전용 버스를 뜻하지 않는다.
layout: network
nodes:
  - id: memory
    label: 메모리
    detail: CPU의 메모리 컨트롤러와 연결되며 PCIe 장치와 같은 채널을 쓰는 것은 아니다.
  - id: cpu
    label: CPU
    detail: 메모리 컨트롤러와 PCIe 포트의 구체적 구성은 프로세서마다 다르다.
  - id: direct
    label: CPU 직결 장치
    detail: '[[NVMe]] SSD나 확장카드의 실제 직결 여부와 폭은 보드 매뉴얼에서 확인한다.'
  - id: shared
    label: 칩셋 쪽 장치
    detail: '[[M.2]] 슬롯도 모델에 따라 이 경로를 사용할 수 있다.'
  - id: chipset
    label: 칩셋
    detail: CPU와의 업링크를 통해 칩셋 쪽 장치의 트래픽을 전달한다.
edges:
  - {from: cpu, to: memory, label: 메모리 채널}
  - {from: cpu, to: direct, label: CPU의 PCIe 링크}
  - {from: cpu, to: chipset, label: 플랫폼별 업링크}
  - {from: chipset, to: shared, label: 칩셋의 장치 연결}
source: https://www.intel.com/content/www/us/en/gaming/resources/what-is-pcie-4-and-why-does-it-matter.html
```

칩셋 쪽 SSD·네트워크·USB 장치를 동시에 사용하면 업링크를 통과하는 데이터가 겹칠 수 있다. 이 공유 조건이 실제 병목이 되는지는 장치 자체의 처리량과 동시 부하에 따라 달라진다. 칩셋 경유라는 이유만으로 모든 작업이 느려진다고 단정할 수 없다.

실제 구성에서는 CPU 모델·메인보드 리비전·장착 슬롯·다른 장치 사용에 따른 Lane 분기와 비활성화 조건을 함께 읽는다. 그림에 없는 스위치나 별도 컨트롤러가 있는 플랫폼도 있다. 저장장치가 보이지 않는 문제는 [[SSD 인식 불량]], 링크의 이론 계산은 [[PCIe 대역폭 비교]]로 이어진다.
